# Sentinel v5 portable model

This package runs the accepted Stage 30 `ensemble_with_graph` CatBoost arm locally,
without Kaggle credentials, checkpoint mounts, or retraining.

## Run

From the repository root:

```bash
.venv/bin/python scripts/run_sentinel_v5_demo.py \
  --scenario demo/sentinel-v5/scenarios.json
```

The command verifies the manifest and every model/calibrator/scenario SHA-256,
loads the three CatBoost members, applies the frozen isotonic calibrators and
thresholds, and requires exact replay of all retained Stage 30 probabilities and
actions before reporting success. It writes the full hash-bound trace to the
temporary path printed as `trace_path`.

Expected model identity:

- arm: `ensemble_with_graph`
- accepted Stage 30 manifest: `ae9c7a0a027d97739fd0556c5ae6d659f7d0846e31076541978b853af2b4b579`
- portable bundle manifest: `52ed4c31d88cd0fc9d3f7557e3addff2044e33bb8991cc7e12a5b70385dbc900`
- frozen arm specification: `c9fe9ed92109eedabf0ed4b9e1dd11b58c27dd87d3a86ec5e00b41f2c9e73878`
- source commit: `40fb4a131da36556d2b8a04564cb62d73152c7c1`

## What the output means

`calibrated_probability`, `model_action`, and `final_action` are generated by the
portable model at runtime. `presentation_ground_truth` is retained separately and
is never passed into the model. The aggregate figures are descriptive metrics for
the 12 curated accepted-checkpoint replay scenarios, not estimates of production
performance.

The scenarios cover legitimate card, A2A, and agentic events; card testing; APP
scam/mule activity; synthetic merchant/refund abuse; agentic intent abuse; and
proportional challenge/review interventions.

## Boundary

The bundle is explicitly `demo_only=true`, `authoritative=false`, and
`accepted_capacity_evidence=false`. It does not change the frozen protocol,
thresholds, accepted checkpoints, or historical results. It is not the official
Stage 70/80 result and must not be described as production, sealed, confirmatory,
or publication evidence. Seed 2404 is not used.
